TRADEFLOW SCANNER TEST WORKFLOW SPEC
BARCODE CAPTURE AND HANDOFF FLOW

Purpose
- This scanner test app validates the barcode capture path before it is merged into the wider TradeFlow flow.
- The app is split into two surfaces: the main launcher page and the scanner tab.
- The goal is simple: capture a barcode quickly, send it to the Apps Script backend, and push it back into the main app input.

Core Rule
- A barcode is not considered delivered until it is stored in Script Properties and returned to the main page.
- The scanner tab is responsible for capture.
- The backend is responsible for temporary storage and history.
- The main page is responsible for displaying the scanned barcode.

                    │  During active scan session,    │
                    │  long-poll using waitForBarcode │
                    └─────────────────────────────────┘
                                      │
                                      ▼
                    ┌─────────────────────────────────┐
                    │  If barcode arrives             │
                    │  update barcode input           │
                    └─────────────────────────────────┘
                                      │
                                      ▼
                    ┌─────────────────────────────────┐
                    │  Clear latest barcode           │

Notes
- This is the primary handoff path.
- The launcher updates the visible input so the operator can confirm what was captured.
- The listener is short-lived and only runs while a scan attempt is active.

9) Polling Fallback Flow
┌─────────────────────────────────────────────────────────────────────────────┐
│ Push listener misses a barcode or times out                                │
└─────────────────────────────────────────────────────────────────────────────┘
                                      │
                                      ▼
                    ┌─────────────────────────────────┐
                    │  Poll getLatestBarcode()        │
                    │  every 1.5 seconds only         │
                    │  during active scan session     │
                    └─────────────────────────────────┘
                                      │
                                      ▼
                    ┌─────────────────────────────────┐
                    │  If new barcode is found        │
                    │  process it and clear it        │
                    └─────────────────────────────────┘

Notes
- Polling is the backup, not the preferred flow.
- It protects the test against long-poll interruptions.
- Polling stops after a barcode is received, the scan tab is closed, or the session expires.

11) Test Roles
Operator
- Open the launcher page.
- Start the scanner tab.
- Scan or type a barcode.
- Confirm the barcode appears back in the launcher input.

Developer / Admin
- Verify deployment URL is correct.
- Verify Apps Script receive and history functions.
- Check debug logs when POST or GET fallback fails.
- Confirm popup, camera, and backend edge cases are handled.

12) Local Test Principles
- Keep the launcher page lightweight and always ready to receive.
- Treat the scanner tab as a temporary capture tool, not the source of truth.
- Persist only the latest handoff value and a short history.
- Prefer automatic return of scanned data over manual copy-paste.
- Always provide a manual or test fallback when camera flow fails.
- Start backend listening only on demand so idle pages do not burn Apps Script quota.

End State
- The scanner test app behaves like a reliable barcode handoff rig:
- open scanner fast
- capture barcode
- send to backend
- return value to launcher
- confirm result visibly
- recover through polling or manual fallback when needed
